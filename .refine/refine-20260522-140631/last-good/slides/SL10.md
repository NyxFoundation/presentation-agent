# 監査が届くのは5分類中3つだけ

<div class="text-sm opacity-60 mb-6">DeFi脆弱性 5カテゴリ — 監査(コード点検)が原理的に届く範囲</div>

<div class="mt-4 text-lg">

| カテゴリ | 内容 | 監査カバレッジ |
| :--- | :--- | :--- |
| A. 価格操作 | Flash Loan 等による相場介入 | ✓ カバー |
| B. 精度・丸め | 整数オーバーフロー (例: Cetus) | ✓ カバー |
| C. ロジック一貫性 | 同一仕様の複数実装のドリフト | △ 部分 |
| **D. 運用・デプロイ設定** | **承認構成・鍵管理 (例: KelpDAO)** | **✗ 外側** |
| **E. 経済モデル** | **設計起因の崩壊 (例: Terra-Luna)** | **✗ 外側** |

</div>

<div class="text-center text-lg font-semibold mt-8">穴の名前は『運用・統制・経済』 — 皆様が20年磨いてきた領域</div>
