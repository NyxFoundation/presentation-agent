- SUIブロックチェーンで最大のAMM

### 事例2: LayerZero / KelpDAO(2026年4月、$292M) — 第7講への伏線

- 2026年4月18日、北朝鮮Lazarus Groupが$292M、約450億円を盗んだ

**重要**: コードを監査しても見つからない問題、運用とデプロイメント設定の問題

## 【12-14分】第5講: 脆弱性の本当の意味 ← ★★★ メインWow

### 大写しスライド

> # 脆弱性とは何か?
> 

> **「桁あふれがある」だけでは脆弱性ではない**
> 

> 本当の脆弱性は:
> 

> **攻撃者が払うコストに対して、得られるリターンが釣り合わないほど大きくなる経路**
> 

> = **コストとリターンの対称性が破れる経路**
> 

### キーメッセージ

- 桁あふれや計算ミスは、それ自体ではなく、**そこから非対称なリターンへの経路があって**初めて脆弱性になる
- 皆さんが普段やっているCWE・OWASPベースのチェックリスト型の監査では、この経路を網羅的にチェックできない
- なぜなら、コストとリターンの組み合わせは無限にあるから
- これが、伝統的な監査が崩壊している根本理由

## 【14-17分】第6講: 現場の生体験① Bug Bounty経済の崩壊 ← ★★★ Wow

### Current Finance 2バグ + 0.18 USDC事件

**我々が発見した2つのバグ(Lendingサービス Current Finance)**

- **Bug 1 (Medium)**: 清算の「資格判定」はEMA価格、「実行」はSpot価格 → 借り手から余分に担保を奪える経路
- **Bug 2 (High)**: グループごとの管理を3箇所で実装、1箇所だけ違う基準 → 健全なグループのユーザーが、関係ない別グループのせいで強制清算

**報酬: 2件合計で 0.18 USDC ≒ 27円**

念のため: これはCurrent Financeが特別ダメだったわけではない。業界平均より真面目に対応している会社。**これはBug Bounty経済全体の構造問題**

### Sherlock stake-to-submit + 賞金凍結 ← 邪悪な構造

**同じSherlockプラットフォームで起きていること**

**[下方向の崩壊]** 2件の脆弱性発見で 0.18 USDC(27円)

**[上方向の崩壊]** 1件報告するのに $250 USDC を担保として預ける(有効なら返金、無効なら没収)

**[さらに邪悪]** 報告者の「有効率」が一定の閾値を下回ると、**過去に獲得した賞金まで凍結**される

どういうことか:

- 例えば、10件報告して2件しか有効と判定されなかった研究者は、その2件の賞金も引き出せなくなる
- 真剣な研究者ほど「安全策として、確実に通る報告しかしない」方向に向かう
- **業界全体が、研究者にペナルティを課す方向に逆行している**

整理すると、同じプラットフォームの中で:

- 真面目に報告しても**27円**
- 報告するのに**$250預けろ**
- **有効率が下がったら過去の賞金も凍結**

これが、AI時代のBug Bounty経済の現実。Sherlockだけを批判している話ではなく、業界全体が、AI時代に対応できていない。

## 【17-20分】第7講: 現場の生体験② SPECAとLayerZero ← ★★★ Wow

### SPECAとは何か(簡潔に)

**SPECA** = Specification-to-Checklist Agentic Auditing(仕様駆動のAI監査フレームワーク)

- 従来のAI監査:「コードから怪しい箇所を探す」
- SPECAのアプローチ:「**仕様書とコードの乖離を探す**」

例: 「清算の判定と実行は同じ基準を使うべき」という仕様 → AIがコード全体を横断して、違う基準を使う箇所を発見

SPECAはICLR 2026のWorkshop on Agents in the Wildに採択

### LayerZero体験談 — 却下された予測と$292M

**時系列**:

**[2025年10月31日]** SPECAがLayerZeroのStarknet DVN実装で「ドメイン分離欠如によるリプレイ脆弱性」を発見、Code4renaに報告

- **ジャッジコメント: "This is a deployment configuration issue, not a security vulnerability"**(却下)

**[5.5ヶ月後 - 2026年4月18日]** LayerZeroのRPC侵害でKelpDAOから$292M流出

### 技術的に何だったか(比喩)

- LayerZeroには、クロスチェーンメッセージを検証する署名者グループがある
- 銀行で言えば、海外送金を承認する複数人の決裁者
- その**承認の電子的な印鑑**に、**どの拠点の決裁か**という情報が刻まれていなかった
- 結果として、**東京支店で押した印鑑が、ニューヨーク支店でも有効になる**状態
- 皆さんの世界の用語で言えば、ナンスや時刻情報の組み込み忘れ、スコープ分離の失敗

### 痛い学び

- 私たちが報告したのは技術メカニズムが違う問題で、KelpDAO事件を直接予測したわけではない
- しかし、両方とも「DVNの信頼前提の脆弱性」という同じカテゴリの問題
- そして、**KelpDAO事件の原因も「デプロイメント構成の問題」**だった
- **コード監査だけでは守れない**
- **「デプロイメント構成は脆弱性ではない」という線引き自体が、もう古い**

## 【20-23分】第8講: AIに任せられない領域 + 皆さんの知見 ← ★★★ メインWow

### スライド1: 質問

「AIには任せられないこと、それは:**運営の正しさをチェックする**こと」

### スライド2(切り替え、大写し): 答え

「これは、**皆さんが20年やってきた仕事**」

### AIには解けない領域

DeFiのハックの相当数は、**コードのバグではなく、運営の不備**でやられている。

KelpDAO事件もコードのバグではなかった。

こういう問題は:

- 金庫の鍵を持つ人が、騙されて悪い人にアクセスを許してしまう
- 意思決定の仕組みが甘くて、1人が勝手に大金を動かせてしまう
- 役割分担が曖昧で、誰がチェックしていないか分からない
- **1人の検証者だけで運用する設定が、ドキュメントで推奨されてしまっている**

→ **皆さんが普段やっている内部統制の話**

- 職務分掌
- 4-eyes原則
- 特権ID管理
- 内部統制(J-SOX)
- **デフォルト設定のセキュリティ・バイ・デザイン**

これらは皆さんが20年積み上げてきた知見。DeFiの世界にはこの知見がほとんどない。DeFiのエンジニアは「コードが正義」の文化で育っていて、組織を統制するという発想がない。

### キーメッセージ(大写し)

> **皆さんが20年やってきた仕事は、世界のDeFiが20年遅れて学ぼうとしていることです**
> 

> 皆さんは既に、**世界が今必要としている知見を、日々の業務で運用している**
> 

### ゼロ知識証明 — 技術的接点

**ゼロ知識証明** = 中身を見せずに正しさだけ証明する暗号技術

比喩: **会計監査の電子署名版**。監査人を信頼しなくても、数学が正しさを保証する。

これを使えば、皆さんの内部統制を、機密を公開せずにDeFi世界に証明できる。
