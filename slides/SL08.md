# Post-competition research plan

| Phase | Research output | Prior work | Novelty | Intended use |
|:--|:--|:--|:--|:--|
| 1. From edition #1 | **Multi-role economic-behavior log dataset** | StockBench (2025) / AI-Trader (2025) / AMA (2025) / StockAgent (2024) — all trader-only trade logs | **First log where trader × hacker × verifier coexist on a single ledger.** Attack txs, audit artifacts, and normal trades joined in one timeline | **NeurIPS**, training/eval data for enterprise agent development |
| 1. From edition #1 | **Multi-role evaluation benchmark on a crypto-asset market** | AgentBench / R-Judge, Cybench / NYU CTF Bench / DARPA AIxCC, StockBench / AMA — each role evaluated separately | **First practical benchmark evaluating multiple-strategy AIs simultaneously on a crypto-asset market** | **ICLR Benchmark, USENIX Security**, industry standard for pre-deployment AI-agent evaluation |
| 2. Discovery-driven | **Pre-deployment DeFi vulnerability discovery by AI attackers** | SoK: DeFi Attacks (Zhou 2023) / TxRay (2026) / FlashSyn (2024) / LookAhead (2024) — all post-hoc analysis or synthetic attacks on historical data | **Vulnerability reports against new protocols/compositions, and the discovery methodology** | **USENIX Security / CCS**, security auditing |
| 3. Longitudinal | **Longitudinal analysis of AI collusion and deception in an economy with real monetary incentives** | Colosseum (2026) / NARCBench (2026) / MAEBE (2025) / Emergent Social Intelligence Risks (2026) — all observed on abstract tasks (DCOP, blackjack, RPG, etc.) | **First longitudinal dataset that accumulates naturally-occurring phenomena in an economy where money is the real incentive**, repeated annually | **NeurIPS, ICML**, governance and control design for multi-agent systems |
| 3. Longitudinal | **Economic-optimization benchmark for AI-agent permission design** | AgenTRIM (2026) / Agent-SafetyBench (2024) / ToolSafe & WebGuard (2025) / EU-Agent-Bench (2025) — all guardrail evaluation under fixed permissions | **First benchmark that treats permission design itself as the optimization variable** and reverse-derives optimal boundaries from profit and max-loss economic outcomes | **USENIX Security / S&P**, permission policy design for enterprise AI agents |
