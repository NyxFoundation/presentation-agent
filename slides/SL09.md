Speaker Notes:

【概要】
S1-B は「暗号で守る」だけでは不十分という話。安全装置が "発火した事実" を後から検証可能に出力できないと、紛争時に何も主張できない。Proof-of-Exploit は社会実装版のフェイルストップ機構で、AI が見つけた脆弱性の存在を ZK 証明として on-chain に出し、コントラクトが自動停止する仕組み。

【重要な前提】
福島第一原発の教訓 — 安全装置が "作動した証拠 / 作動しなかった証拠" を独立に検証する手段がなかった。同じ問題はあらゆるデジタル機構で起きる。Proof-of-Exploit は「安全装置の発火 = ZK 証明の検証成功」と等価にすることで、紛争時に物理的に検証できる証拠を残す。なお Proof-of-Exploit は 2024-25 年に 0xPARC / EF research を中心に議論されている設計パターンで、production deployment はまだ限定的。

【概念図の読み方】
上段 OFF-CHAIN: AI Auditor がコントラクトを常時 audit、見つけた witness W を ZK Prover に渡し、π = ZK{ ∃W : exploit(W,C) = drain } を生成。
下段 ON-CHAIN: ZK Verifier (コントラクト内蔵) が π を受理 → Circuit-Breaker が発火 → DeFi Contract が pause。
垂直の wire は OFF-CHAIN で作った π が ON-CHAIN に submit される瞬間を表す。

【各 phase の物語】
phase 0 — 通常稼働: AI Auditor が緑の scan beam で DeFi Contract を監視。verifier も breaker も idle。脆弱性は未発見。
phase 1 — AI が exploit witness W を発見 (amber alert)。DeFi Contract に bug 印。ただし攻撃は実行しない (drain しない)。
phase 2 — AI は W を ZK Prover に渡す。Prover が π を生成 (indigo active)。π badge が Prover の右端に現れる。
phase 3 — π が垂直に on-chain Verifier へ submit される (indigo particle が降りる)。
phase 4 — Verifier が π を受理 (✓ chip 出現、shield が emerald に)。これで "exploit 可能性が暗号的に確定" した。
phase 5 — Verifier が Circuit-Breaker をトリガー (red wire flow + spark)、DeFi Contract が halted (lock + drain prevented banner)。π は on-chain log に永続記録 (左下の "π ON-CHAIN ∀ time")。Drain は起きていない。

【講義での強調点】
- "暗号で守る" だけでなく "守れた事実" "破られた事実" を検証可能にすることが重要。これが福島の教訓を社会実装版に変換した姿。
- 従来の検知系との対比 (発話だけで触れる):
  • 正しさの保証: 運営の主張 → 数学的 ZK proof
  • 機密性: exploit 公開 → witness は秘匿のまま π だけ on-chain
  • 自動化: 人手介在 → contract が自動 pause
  • 紛争時の証拠: 改ざん可能なログ → 暗号的に拘束された on-chain proof
- 本図では drain が起きていない。これは ZK proof が exploit より先に on-chain に届いたシナリオ。実際の deployment では proof 生成時間との競争が課題で、これは S3-B 罠 #4 "witness generation がボトルネック" の伏線。
- 「W は秘密のまま」がポイント: ZK 性により Verifier には exploit の内容を見せず "存在することだけ" を伝える。同じ手法で responsible disclosure を強制可能。
- KelpDAO 例との接続: Proof-of-Exploit は「攻撃の事実を on-chain で発火させる」モデル。S1-A の "攻撃側のスコープに守備が追いつかない" 問題に対して、暗号で "発火した事実" 自体を作る側に回す発想。
- ホワイトボードへの伏線: 午後 KelpDAO のホワイトボードで「ZK light client なら防げたか?」と同じ系譜の議論を行う。
