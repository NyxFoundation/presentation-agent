Speaker Notes:

【概要】
S1 の最後に「証明 (proof)」という言葉の 3 つの意味を整理する。これは S2 以降で「ZK 証明」を扱うときの土台になる前提。混同を避けたいのは「ZK 証明は数学的に正しい」という言い方 — これは厳密ではない。

【概念図の読み方 (静的図。生成スクリプト: figures/proof_meanings.py)】
3 列とも同じ行構造 (ヘッダ → 証明の実体 → 敵対者 → 例)。列を縦に読めば各概念、行を横に読めば違いが分かる。
- ① 数学的証明: 公理系から formal logic で定理を導出。敵対者は存在しない (破線ゴースト = 不在)。誤りの確率 0、時間に依らない。例: フェルマーの最終定理。
- ② 情報論的暗号証明: Prover が π (実体は大きな数字 / hex) を送り、Verifier が固定の式 (g^z ≡ a·y^c、Σ-protocol の検証) をチェックする。下の赤い敵対者は計算能力 ∞ でも破れない (確率 1) — 攻撃の赤い矢印は wire の手前で × に阻まれる。例: One-Time Pad、Σ-protocol。
- ③ 計算論的暗号証明: 構造は ② とまったく同じ (Prover → π → Verifier の式チェック)。違いは敵対者が多項式時間である仮定と、DL / RSA / LWE などの困難性仮定が前提に入ること (敵対者の下の amber 注記)。偽造確率は negl(λ)。例: 電子署名、SNARKs。
- ③ を破線バンドで囲い「ZK の「証明」はここ」— タイトルの問いへの答え。ZK 証明 (と本講義で扱う暗号すべて) は ③ の系譜。
- 口頭で補足: ① は adversary を想定しない命題、②③ は adversary を含むセキュリティゲームについての命題。違いは adversary の計算量と hardness assumption の有無だけ (旧・図下注釈の内容)。

【講義での強調点】
- "ZK 証明は数学的に正しい" は厳密でない。① と ③ を混同しない。計算量仮定が破れれば protocol も破れる。
- ② と ③ の構造はほぼ同じで、違いは「敵対者の計算量」と「仮定が必要かどうか」の 2 点だけ — 図でも ② と ③ の Prover/Verifier/式チェックが同型であることを指差して見せる。
- 暗号証明は「Verifier が固定の equation を check して通れば OK」だけ — π という大きな数字が equation を満たす能力だけが意味を持つ。これが ZK の構造的特徴 (S2-A の伏線)。
- ① は本講義の射程外だが、混同を防ぐために置いた。Wiles の Fermat 証明は紙とインクで peer-review されたもので、暗号と無関係。
- 2026 年: 量子計算機が成熟すれば RSA・ECDSA など多くの ③ が崩れる。だから lattice (LWE) 系や hash 系 (FRI / Brakedown) への移行が進む。"③ に賭ける" は永続ではなく "現時点で最良" という意味。
- S2 の橋渡し: 次から ZK / MPC / FHE を見ていくが、すべて ③ の系譜。仮定下で偽造不可能。仮定を選び・組み合わせる設計が Programmable Cryptography の中身。
