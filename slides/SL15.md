Speaker Notes:
【概要】0xPARC の "Programmable Cryptography" を 3 段 pipeline で示す。本質は「普通のプログラムコードが、暗号計算の数学的回路にコンパイルされ、ユーザが使える実行可能 app になる」という流れ。ZK/MPC/FHE は backend の違いに過ぎず、pipeline 自体は共通。

【図の読み方】左から右に 3 ステージ。
- **Stage 1: Source** — Developer が `.rs` / circom / noir 等で「何を計算するか」を高級言語で書く。暗号の知識は不要、通常の関数定義。`#[private]` / `#[public]` で「何を隠すか」を宣言する syntax あり。
- **Stage 2: Arithmetic Circuit** — compiler が高級言語を gates + wires (R1CS / 多項式制約系) に変換。これが ZK/MPC/FHE 共通の数学的表現。
- **Stage 3: Executable** — backend (prover/protocol/FHE eval) に乗せて実行可能 app に。end user は内部の暗号を意識しない。
- 下に「用途別 alignment」 — 同じ pipeline でも書くロジックの種類で backend が決まる例:
  - ZK 系: 年齢証明 「今日 − 生年月日 ≥ 18 年」(prover が秘密を出さず検証)
  - MPC 系: 秘密入札 「max(bid₁, bid₂, bid₃)」(各社の入札額を漏らさず)
  - FHE 系: 暗号文 AI 診断 「diagnose(E(medical_data))」(暗号化のまま推論)

【動きについて】
phase 進行はなく、3 ステージすべてが常時表示で、compile / run の粒子が常時循環している (SL14 と同じ設計)。どの瞬間で止めても「Source 3 種 → compile hub → Circuit → run → Executable」の全体構造がそのまま読めるので、講師は好きなタイミングで任意のステージを指差して説明してよい。左の 3 エディタの色 (amber=ZK / cyan=MPC / purple=FHE) と粒子の色が対応している。

【講義での強調点】
- 「programmable」の核心: <strong>「任意の関数を高級言語で書ける」</strong> → 「compiler が暗号回路に落とす」 (0xPARC intro book の比喩: 単機能ハードウェア → smartphone)
- ZK/MPC/FHE は backend の選択に過ぎず、開発者から見れば「同じ pipeline」
- Stage 2 の arithmetic circuit が ZK/MPC/FHE 共通の中間表現 ─ これが composition (次スライド) を可能にする基盤
- Stage 1 の `#[private]` / `#[public]` 宣言が「何を隠すか」を決める ─ backend がそれを実現する方法は backend 次第
- 4 つの core primitive (MPC / SNARK / FHE / ORAM) を全部この pipeline で書ける。ORAM は access pattern の隠匿用途
- 合成パターン (threshold FHE / coSNARK / Verifiable FHE 等) の詳細はここでは扱わない。「複数の backend を組み合わせられる」ことだけ口頭で一言触れ、次の S2-C (最前線) へ進む
- Open Question: 「自分のプロジェクトで何を `private` にしたいか、ロジックは何か、どの backend が向くか」── pipeline の各段で考える設計演習
