Speaker Notes:
【概要】Programmable Cryptography が実装される代表的な合成パターンを 7 つ、1 枚で循環表示する。各カードは「左 primitive + 右 primitive/standard → application」のパターンに揃え、視聴者は「同じ型に当てはまる組み合わせ」として認識できる。

【図の読み方】4×2 グリッドに 7 カード全並列表示。各カード = (index ①〜⑦) + app 名 (太字) + recipe (formula) + 1 行解説。色は合成に関わる primitive で色分け (ZK=黄、MPC=水、FHE=紫、ML=ピンク、Multisig=青、Bridge=緑)。

【各カードの中身】
① ZK over 既存暗号 (Longfellow) — ECDSA / SHA-256 / mDOC / JWT / W3C VC を破壊せず ZK 化。社会実装の象徴。
② ZK + FHE (Verifiable FHE) — FHE の盲点「計算正しさ」を ZK で塞ぐ。S2-A の最終 phase で見た合成。
③ MPC + FHE (threshold FHE) — 鍵分散 + 計算秘匿。Zama が NIST に提出している方向。
④ ZK + ML (zkML) — モデル推論の正しさを暗号的に保証。EZKL / ezkl-poc 系。
⑤ MPC + ML (mpcML / 連邦学習) — 各人の学習データを秘匿しつつ共同学習。
⑥ ZK + Multisig (Proof of Multisig Op) — Nyx の方向。Multisig 操作を秘匿しつつ正しさを証明。
⑦ ZK + Bridge (ZK Light Client) — cross-chain message + state proof。S2-C ⑤ で詳細を見る。

【講義での強調点】
- 列を入れ替えても文意が通るパターンが「実装上素直」。FHE + ZK と書いても同じ。
- ただし合成順序が出力性質を決める場合がある: ZK-of-FHE-decryption と FHE-of-ZK-proof は別物 (罠の伏線)
- 振り返り: 皆さんのプロジェクトテーマで使う合成はどの行に当たるか — Track C で書き出す
- 「7 つあるが、ZK が 5 回登場」が観察ポイント — ZK が現代暗号合成の中心ハブ
- ⑦ ZK + Bridge は午後ホワイトボード (KelpDAO) と直結
