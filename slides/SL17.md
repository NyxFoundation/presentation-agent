【概要】
S2-C を 1 枚に統合したスライド。縦軸は「prover オーバーヘッド = 同じ計算を native 実行に比べて何倍遅く証明できるか」(log)。下ほど速い。10 年で 10⁶-10⁷ 倍 → 10⁵ 倍未満、つまり 2 桁の高速化。

【3 系統の分類 (色で読む) — ここを混同しないのが本日の要点】
- グレー = pairing 系: Groth16 (2016)。証明は最小 (~200B)・検証最速だが、trusted setup が必要で、回路ごとのセットアップと大きな prover オーバーヘッド (Thaler の分析で 10⁶-10⁷ 倍相当)。Groth16 は Sumcheck 系ではない。
- 青 = STARK / FRI 系: hash ベースで trusted setup 不要・耐量子。RISC Zero、SP1 (Turbo まで)、StarkWare Stwo (circle STARK、2025 年 Starknet mainnet 稼働)。zkVM を最初に実用化した系統だが、オーバーヘッドは ~10⁶ 倍で横ばいだった (Thaler, 2025/3: 「1 年前とほぼ同じ」)。
- amber = Sumcheck 系: LFKN 1992 の対話証明理論 → Thaler 2013 (structured ME 上で concretely efficient — 無条件に「線形時間」とは言わない) → Lasso 2023 (lookup argument) → Jolt (a16z)。Jolt は 2025/8 に prover オーバーヘッド 10⁵ 倍未満・ラップトップ単体で 500 kHz 超 (32 コアで 1 MHz 超) を公表 — 他 zkVM 比で 1 桁改善。SP1 も Hypercube (2025/5) で univariate STARK から Sumcheck 系 (multilinear + LogUp GKR) に全面刷新して real-time proving を達成 (p8 のグラフの正体)。
- green カード = MPC-in-the-head 系 (別系統): Ligero (2017) → Longfellow (Frigo & shelat, eprint 2024/2010)。zkVM とは解く問題が違うのでこの軸には乗せない — 既存 ID (mDL の ECDSA + SHA-256 署名) を発行者側の変更ゼロでそのまま ZK 化する。スマホ実測で ECDSA 証明 ~20ms、mDL 提示証明は数百 ms。Google Wallet で 2025 年から稼働、Trail of Bits + Ligero の監査済み OSS。EUDI Wallet 採用検討・IETF 標準化議論へ。

【物語 (口頭)】
2016 年の Groth16 は「証明は小さいが作るのが遅い、しかも回路ごとに儀式 (trusted setup) が要る」世界だった。STARK 系が setup を消して zkVM を実用化し、Sumcheck 系がオーバーヘッドの壁を破った。並行して MPC-in-the-head 系は「既存の身分証をそのまま ZK 化する」という別の出口から社会実装に到達した。系統 (仮定・数学) が違えば得意な出口も違う — S3 の技術選定 (p19 の 4 つの問い) の土台になる見取り図。

【数値の扱い (質問されたら)】
- オーバーヘッド値は Justin Thaler (a16z) の公表分析と Jolt チームの公表ベンチに基づく。ベンチマークは witness 生成を含むか等で大きく変わる (罠 #4) ので、桁 (オーダー) だけを読む。
- Groth16 の 10⁶-10⁷ は「バックエンド ~100×|C| 群演算 + frontend の回路化コスト」を合わせた Thaler 2022 の分析値で、単一の実測論文値ではない。
