# S2-C ③ コミットメント + Folding の進化 — <strong>trusted setup を捨てる流れ</strong>

<div class="grid grid-cols-2 gap-6 mt-2">

<div>

### コミットメントの進化

```mermaid {scale: 0.65}
graph LR
  A[KZG<br/>pairing<br/>trusted setup] --> B[FRI<br/>hash-based]
  B --> C[Brakedown<br/>linear-time]
  B --> D[Ligero<br/>sublinear arg]
  B --> E[BaseFold<br/>2024+]
  style A fill:#fee2e2,stroke:#cc3333
  style E fill:#dcfce7,stroke:#2c7a3f
```

<div class="mt-3 text-xs">

<strong>利点</strong>:
<ul class="list-disc pl-5">
<li>trusted setup 不要 (universal でも避けたい)</li>
<li>量子耐性 (post-quantum)</li>
<li>Blake3 などで <strong>hashing が高速</strong></li>
</ul>

</div>

</div>

<div>

### Folding / IVC の進化 (別系統が並走)

```mermaid {scale: 0.65}
graph LR
  H[Halo2<br/>accumulation<br/>+ Plonkish]
  N[Nova<br/>folding scheme] --> L25[LatticeFold+<br/>2025]
  N --> H25[Hash-based<br/>folding 25-26]
  H -.別系統.-> N
  style L25 fill:#dcfce7,stroke:#2c7a3f
  style H25 fill:#dcfce7,stroke:#2c7a3f
```

<div class="mt-3 text-xs">

<strong>用途</strong>:
<ul class="list-disc pl-5">
<li><strong>IVC (Incrementally Verifiable Computation)</strong> で「永続的に積み上がる計算」を1つの proof に圧縮</li>
<li>ブロックチェーンの state proof, zkML の長い推論</li>
</ul>

</div>

</div>

</div>

<div class="mt-4 rounded-xl border border-gray-300 bg-gray-50 p-3 text-xs">

<strong>まとめ</strong>: 「証明系」「コミットメント」「合成 (folding)」の3つが同時に hash-based / setup-free に動いている。<strong>10年前の SNARK の常識は通用しない</strong>。

</div>
